# Production Firebase security architecture

## Deployed model

- Firebase project: `inter-level-progress-manager`.
- Fixed Web App ID: `1:379503088311:web:ff8ed9b3c2540b9b133332`.
- Canonical app key: `quizProjectionApp2`.
- All app documents remain below `/apps/quizProjectionApp2/users/{ownerUid}/...`.
- Administrator state is stored at `data/state`; server-only lookup and session documents use `invigilatorCodes` and `invigilatorSessions` below the same owner namespace.

Administrators authenticate with Google. Both the browser and every administrator callable require an active Firebase Access Manager grant for the fixed Web App ID, including app registration and grant-expiration checks.

Invigilator codes are generated by `quizProjectionCreateCode`. A code contains the owner UID solely to route the server to the isolated owner namespace plus a 12-character cryptographically random secret. The lookup uses a SHA-256 code hash. The complete code is visible only in the authorized owner's state so it can be copied and distributed by the administrator.

`quizProjectionRedeemCode` validates the code, quiz setting, revocation, and expiration, then mints a dedicated 12-hour-or-shorter opaque bearer session containing a 256-bit random secret. Only its SHA-256 hash is stored in Firestore, and the browser keeps the token in session storage. The invigilator device does not need Firebase Authentication, Google login, or an administrator session.

Existing six-digit and named codes are supported through a compatibility lookup that enumerates only owner documents below `/apps/quizProjectionApp2/users`. The redemption Function is capped at two instances and rate-limits attempts per instance. New codes continue to use the stronger routed format.

`quizProjectionGetSessionState` returns only the assigned teams, their scores, quiz questions, and narrow session permissions. It strips all other access codes and audit records.

`quizProjectionSubmitScore` uses a Firestore transaction and revalidates the session, expiration, revocation, assigned team, question status, quiz status, read-only flag, score state, and mark bounds. Every accepted change creates an invigilator audit entry. The administrator's existing Firestore listener receives the updated state in real time.

`quizProjectionRevokeSession` requires the authorized owner, marks the access record revoked, and removes its code lookup. Existing sessions fail their next refresh or score request because every callable revalidates the access record.

## Deployed callable Functions

- `quizProjectionCreateCode`
- `quizProjectionRedeemCode`
- `quizProjectionGetSessionState`
- `quizProjectionSubmitScore`
- `quizProjectionRevokeSession`

Functions are deployed only by explicitly naming them. Hosting is deployed only with `firebase deploy --only hosting:quiz-projection-app2`. No Firestore or Storage rule files are owned or deployed by this repository; canonical rules remain in `jeevanvarghese579/school-softwares-firebase-shared-config`.
